# OrderSMC-DAG

OrderSMC-DAG performs candidate-restricted Bayesian structure learning by applying sequential Monte Carlo to topological orders and analytically averaging compatible parent sets. The implementation supports continuous, binary, and categorical variables, deterministic candidate artifacts, local and MPI execution, exact small-graph validation, and reproducibility diagnostics.

This repository is the conference-submission codebase. It contains one active implementation and one lean experimental protocol; superseded model copies, generated datasets, run outputs, caches, and historical protocol machinery are intentionally excluded.

## Repository layout

The active implementation is **v0.7.0**. See
[sampler corrections and migration](docs/SAMPLER_CORRECTIONS_V07.md) for the
MPI proposal fix, uniform-start adaptive bridge, uncertainty semantics, and
the paired validation pilot. Historical result snapshots are unchanged.

- `src/ordersmc/`: the OrderSMC implementation and command-line interface.
- `tests/`: model, score, graph-summary, replay, and MPI smoke tests.
- `docs/METHODOLOGY.md`: mathematical target, mixed local scores, candidates, and limitations.
- `examples/`: small configurations and local/MPI examples.
- `experiments/`: Version 3 protocol, deterministic cohort plans, synthetic generator, exact references, Order MCMC, metrics, and validation tests.

## Installation

Python 3.10 or later is required.

```bash
python -m pip install -e '.[test]'
python -m pytest -q
```

For MPI support:

```bash
python -m pip install -e '.[mpi,test]'
mpirun -np 2 python tests/mpi_smoke.py
```

Install the experiment harness separately:

```bash
python -m pip install -e './experiments[test]'
python -m pytest -q experiments/tests
```

## Minimal example

```python
import pandas as pd
from ordersmc import OrderSMCConfig, fit, infer_metadata_and_encode

raw = pd.read_csv("data.csv")
data, variable_types, cardinalities = infer_metadata_and_encode(raw)
config = OrderSMCConfig.preset("standard", seed=202)
result = fit(data, variable_types, cardinalities, config=config)

print(result.edge_table().head(20))
```

For final analyses, review and save explicit variable metadata instead of relying on automatic type inference. See `examples/` and `docs/METHODOLOGY.md` for candidate-table construction, checkpointing, MPI, and interpretation of posterior edge probabilities.

For data generated by a restricted conditional-Gaussian Bayesian network, set
`score_method="clg-bic"`. This explicitly forbids continuous parents of
discrete children and uses hyperparameter-free multinomial/Gaussian BIC local
scores. The default `native` mixed score remains available for more general
mixed-family graphs; the two choices define different statistical models and
must not be switched silently after inspecting results.

An opt-in [experimental rank-native score](docs/RANK_NATIVE.md) uses deterministic
normal scores for continuous columns and preserves discrete encodings. It is a
plug-in robustness model, not an original-scale marginal likelihood; the native
default is unchanged. Its frozen development comparison is launched with
`bash scripts/submit_rank_validation.sh`.

The [matched rank-native competitor follow-up](experiments/RANK_COMPETITOR_PROTOCOL.md)
reuses those fixed datasets and accepted SMC fits, adding five shared-score
comparators and longer-chain reproducibility checks. Its staged launcher is
`bash scripts/submit_rank_competitors.sh`; it is a development comparison,
separate from both historical V3 results and the metadata-matched synthetic pilot.

An optional [uncertainty-aware graph display](docs/UNCERTAINTY_SUMMARIES.md)
preserves the representative DAG's skeleton while leaving weakly supported
directions unresolved. It does not change the posterior or replace original
recovery metrics, and it is not a CPDAG or a causal-identification guarantee.

## Reproducing the paper design

The current computational follow-up is documented in
[parallel SMC scaling and quality-versus-time](docs/SCALING_QUALITY.md).
Run `bash scripts/submit_scaling_quality.sh` for its frozen, environment-activating
Slurm workflow. It separates fixed-work MPI speedup, synthetic-truth graph recovery,
and empirical MCMC agreement; it does not assume a converged large-network reference.
Historical timing fits and their convergence/time-limit failures remain preserved.

The authoritative specification is [`experiments/PROTOCOL.md`](experiments/PROTOCOL.md), with a rendered [`experiments/PROTOCOL.pdf`](experiments/PROTOCOL.pdf). It defines one mandatory mathematical validation gate and four experiments: exact posterior validation, the mixed-data benchmark, difficult-posterior time-to-accuracy, and MPI strong scaling. The pilot-selected settings and immutable source-result hashes are recorded in [`experiments/configs/pilot_freeze_v3.json`](experiments/configs/pilot_freeze_v3.json).

The separate metadata-calibrated synthetic validation for the Living Brain
paper is specified in
[`experiments/SECTION2_METADATA_PROTOCOL.md`](experiments/SECTION2_METADATA_PROTOCOL.md).
Its staged cluster commands and output tables are documented in
[`experiments/README.md`](experiments/README.md); this phase uses aggregate
statistics only and never imports participant-level observations or inferred
biological edges as synthetic truth.

Run the mandatory score validation and create deterministic plans without generating data:

```bash
ordersmc-experiments validate-scores --full --strict --output g0-score-validation.json
ordersmc-experiments plan e1 --master-seed 20260815 --output e1-plan.json
ordersmc-experiments plan e2 --master-seed 20260815 --output e2-plan.json
ordersmc-experiments plan e3 --master-seed 20260815 --output e3-plan.json
ordersmc-experiments plan e4 --master-seed 20260815 --output e4-plan.json
```

Generate and replay-check one mixed dataset:

```bash
ordersmc-experiments generate \
  --output dataset-e1-example \
  --d 8 --n-train 160 --max-indegree 2 \
  --master-seed 20260815 --experiment-id e1 \
  --cell-id d008-random-order --replicate-id 0

ordersmc-experiments replay-dataset dataset-e1-example
```

The method registry is deliberately honest:

```bash
ordersmc-experiments registry
```

Exact Order DP, OrderSMC, Order MCMC, Partition MCMC, and REV-MCMC are included. The two structure-target adapters have exhaustive tiny-state acceptance tests; see [`experiments/ADAPTERS.md`](experiments/ADAPTERS.md). DAG-GFlowNet and BCDNets remain explicit optional adapter-gated candidates and are not scheduled by E1--E4.

The Slurm entry points are `scripts/submit_e1.sh` through `scripts/submit_e4.sh`. Every workflow runs the score and sampler-adapter preflight before preparing data or launching inference.

## Reproducibility expectations

Every released result should record the protocol version, source revision, environment, configuration and candidate-table hashes, dataset manifest, seed record, backend, MPI layout, raw per-seed output, and aggregation command. Seeds are repeated measurements nested within independently generated graph--dataset pairs; they are never treated as independent datasets in confidence intervals.
